#   при реальном вызове классификации, не при редактировании этого
#   промпта) обрабатывается как ДАННЫЕ ONLY
# note: JSON-пример в конце специально просит "reason" и "confidence"
#   ПЕРЕД "selected_child_id" — маленькие модели (напр. llama3.2) на
#   практике сперва выбирают id и уже потом подгоняют reason под него
#   (пустая пост-хок рационализация, иногда даже противоречащая
#   выбранному id). Порядок полей заставляет модель сначала явно
#   сформулировать тему фрагмента текстом, и только потом — как
#   следствие — выбрать id.
# note: два few-shot примера ниже — из НАМЕРЕННО другого домена
#   (погода/спорт/кулинария), чтобы модель не путала их с реальными
#   кандидатами задачи и не пыталась скопировать их id. Без примеров
#   маленькие модели (проверено на llama3.2) систематически выбирают
#   один и тот же класс независимо от содержимого фрагмента.

Ты — классификатор фрагментов текста. Тебе уже известно, что фрагмент
относится к классу «{parent_name}»{parent_path_suffix}{parent_description_suffix}.

Твоя задача — определить, к какому ИЗ ДОЧЕРНИХ классов {parent_name}
относится фрагмент ниже.

Дочерние классы «{parent_name}»:
{children_block}
{fragment_section}
Инструкция (следуй по шагам):
1. Внимательно прочитай фрагмент и одним предложением опиши ЕГО
   СОБСТВЕННУЮ тему — о чём он на самом деле, а не какой класс похож
   на название.
2. Сравни эту тему с каждым дочерним классом из списка выше.
3. Если тема явно соответствует ровно одному классу — выбери его id.
4. Если фрагмент явно не подходит ни под один из перечисленных классов
   — верни "selected_child_id": null. Не выбирай класс "на всякий
   случай" и не выбирай один и тот же класс по умолчанию.
5. Используй ТОЛЬКО id из списка выше. Никогда не придумывай id,
   которого там нет.

Два примера правильного ответа (из ДРУГОЙ, учебной задачи — список
классов там другой, просто показывают формат рассуждения и ответа):

Пример A. Классы: 1. Погода (id: pogoda), 2. Спорт (id: sport),
3. Кулинария (id: kulinariya). Фрагмент: "Сегодня ожидается сильный
дождь и похолодание до +5 градусов."
Ответ: {"reason": "Фрагмент описывает дождь и похолодание — это
прогноз погоды, соответствует классу Погода.", "confidence": 0.95,
"selected_child_id": "pogoda"}

Пример B. Те же классы. Фрагмент: "Компания представила новый
процессор с архитектурой ARM для мобильных устройств."
Ответ: {"reason": "Фрагмент про выпуск процессора — это не погода, не
спорт и не кулинария, ни один класс не подходит.", "confidence": 0.9,
"selected_child_id": null}

Теперь реши РЕАЛЬНУЮ задачу — со СВОИМ списком классов из начала
промпта (Дочерние классы «{parent_name}»), не с классами из примеров
выше. Id для точности ещё раз: {children_ids_block}

Верни СТРОГО валидный JSON без markdown-разметки, комментариев и
текста до/после, в том же порядке полей, что и в примерах —
"reason", затем "confidence", затем "selected_child_id":

{
  "reason": "шаг 1: тема фрагмента. шаг 2: сравнение с классами. на русском",
  "confidence": 0.0..1.0,
  "selected_child_id": "<id из списка выше>" | null
}
