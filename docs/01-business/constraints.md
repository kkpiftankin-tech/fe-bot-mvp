# Ограничения

Жёсткие границы, формирующие каждое архитектурное решение. Если предложение нарушает ограничение — меняется предложение, а не ограничение.

## Технические ограничения

### C-01. Маленькая локальная LLM

Модель по умолчанию — `llama3.2:latest`, запускаемая через локальный Ollama. Промпты, схемы и валидаторы обязаны работать в предположении маленькой, склонной к дрейфу модели.

**Следствие.**

- Промпты узкие (одна фаза, одно решение, одна схема).
- Выводы LLM валидируются перед потреблением.
- Не закладываемся на длинный контекст и chain-of-thought.

**Зафиксированное исключение.** Многоуровневая классификация фрагментов по дереву классификаторов (Setup, [SETUP-13](../02-system/features/SETUP-13-classifier-library.md)) использует `qwen2.5:7b`: `llama3.2` на живых тестах систематически не различал содержание фрагментов (`DEFAULT_CLASSIFIER_MODEL` в `schemas/common/defaults.py`, [ADR-HTC-09](../03-architecture/adr/ADR-HTC-09-generic-tree-classifier-library.md)). Остальные LLM-задачи остаются на `llama3.2`.

### C-02. Только JSON, где ожидается схема

Каждый агентный вывод с Pydantic-схемой ОБЯЗАН быть одним JSON-объектом, соответствующим этой схеме. Никакой прозы-преамбулы, никаких markdown-фенсов внутри JSON.

**Следствие.**

- Repair-петли при ошибке парсинга подают агенту отчёт валидатора.
- Свободный текст разрешён только вне узлов структурированного вывода.

### C-03. Датасеты строит Python, а не LLM

LLM формирует `GenerationSpec`; строки создаёт Python-worker.

**Следствие.**

- Ни один агент никогда не возвращает содержимое `X_train` или `y_train`.
- Воспроизводимость определяется `random_state` и кодом worker-а.

### C-04. У RAG-карточек обязательна metadata

Каждая карточка в [rag/cards/](../../rag/cards/) обязана содержать `doc_id`, `doc_type`, `phase`, `domain`, `data_source`, `task_type`, `retrieval_tags`, `confidence_level`, `version`, `owner`. Карточка без metadata не извлекаема.

**Следствие.**

- `rag_metadata_validator` входит в ingestion-CI.
- Generic свободные тексты идут в [incoming-docs/raw/](../../incoming-docs/raw/), а не в `rag/cards/`.

### C-05. ContextMemory — единственный носитель состояния

Узлы LangGraph никогда не читают состояние из истории чата. Они читают и пишут типизированный `ContextMemory`.

**Следствие.**

- Персистентность диалога ключуется `conversation_id`, в ней лежит сериализованный `ContextMemory`.
- Долгосрочная межсессионная память — вне scope MVP.

### C-06. Никаких проприетарных frontier-моделей в дефолтном пути

Дефолтный путь разработки и CI использует Ollama + open-weights модели. Интеграции с облачными LLM — опциональные адаптеры, никогда не обязательные для работающего билда.

## Операционные ограничения

### C-07. Local-first deploy

Полный стек обязан подниматься на одном ноутбуке через `docker compose --profile infra --profile llm --profile app`. Никаких обязательных облачных сервисов в MVP.

### C-08. Потолок ресурсов для локальной разработки

Дефолтный Compose-профиль обязан работать в ≤ 16 GB RAM на consumer-ноутбуке с 4 ядрами (или CPU-only inference для `llama3.2`).

### C-09. Детерминированность важнее креатива

Дефолтная семплинг-температура LLM низкая. Где могут быть предложены несколько правдоподобных признаков, RAG evidence сужает выбор, а не стилистические вариации LLM.

## Организационные / процессные ограничения

### C-10. Docs-as-code не подлежит обсуждению

В `src/` нельзя писать код раньше, чем появятся docs и schemas, от которых он зависит. См. [docs/00-methodology/development-process.md](../00-methodology/development-process.md).

### C-11. У каждого агента — spec, schema, prompt, validator и test

Перечислены в [AGENTS.md](../../AGENTS.md). Отсутствие любого из них — блокер релиза.

### C-12. Traceability-матрица обновляется при каждом изменении

Каждый PR, добавляющий агента, контракт, семейство карточек или фичу, обновляет соответствующую таблицу в [docs/traceability/](../traceability/).

## Вне scope (как следствие ограничений)

- Обучение, хостинг или serving production-моделей.
- Multi-tenant изоляция шире per-conversation.
- Real-time / streaming ML.
- Автоматические циклы дообучения.
- Облачный managed RAG (Pinecone и т. п.) в дефолтном пути.
