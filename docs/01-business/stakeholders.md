# Стейкхолдеры

Роли, которые взаимодействуют с FE-Bot или влияют на его дизайн. Используйте эту страницу при решении, кто должен ревьюить изменение.

## Основные пользователи

### ML-инженер / Data Scientist (конечный пользователь)

- **Хочет.** Управляемый способ стартовать новую ML-задачу без переизобретения каркаса.
- **Вход.** Однострочное описание задачи, опционально — резюме сэмпла данных (описание, а не сами данные), опционально — подсказка по домену. Далее — ответы на уточняющие вопросы и подтверждения (набор признаков, модель).
- **Выход.** `archive.zip`-пакет с признаками, синтетическим датасетом, training config, pipeline (состав — в [system-overview.md](../02-system/system-overview.md#runtime-выход)).
- **Боли.** Повторяющийся feature engineering, разрозненные доменные заметки, хрупкие одноразовые скрипты.
- **Ожидание доверия.** Хочет видеть evidence (`evidence_doc_ids`) за каждым предложенным признаком.

### Аналитик / Доменный SME

- **Хочет.** Способ убедиться, что предложенные признаки соответствуют доменным ожиданиям.
- **Вход.** Читает `FeatureSpec`, `ValidationReport`, RAG-карточки (evidence).
- **Выход.** Обратная связь по кандидатам (`approved` / `rejected` с причинами).
- **Ожидание доверия.** Признаки, верные домену; никаких выдуманных полей.

## Операционные стейкхолдеры

### Администратор базы знаний RAG

- **Хочет.** Постоянный способ онбординга новых доменов (новые schema, feature, analytics, validation-карточки) без поломки retrieval.
- **Вход.** Сырые доменные документы (`md`, `txt`, `pdf`, `docx`, `xlsx`, `csv`, `json`), которые загружаются через Setup-мастер; для разработки репозитория — также [incoming-docs/raw/](../../incoming-docs/raw/). Параметры проекта (домен, теги, embedding-модель) и решения по сгенерированным карточкам.
- **Выход.** Опубликованная версия базы знаний (`kb_version`) со сигналом «Knowledge Base ready»; валидированные карточки с metadata, проходящей `rag_metadata_validator`.
- **Инструменты.** Setup-мастер ([SETUP-01](../02-system/features/SETUP-01-setup-wizard.md)); для работы с репозиторием — [.claude/skills/ingest-docs/](../../.claude/skills/ingest-docs/), [.claude/skills/generate-rag-cards/](../../.claude/skills/generate-rag-cards/).
- **Права.** Публикация базы знаний требует роли `rag_admin` или `admin` с правом publish ([SETUP-01 §4.3](../02-system/features/SETUP-01-setup-wizard.md)).

### Product / Platform-owner (потребитель Analytics)

- **Хочет.** Видеть, как пользователи проходят Setup и Runtime, где теряются, насколько хорош retrieval и откуда взялся каждый экспортированный артефакт.
- **Вход.** Почти ничего не вводит — читает дашборды ([ANALYTICS-01..09](../02-system/features/feature-index.md)).
- **Выход.** Решения о приоритетах: что чинить в базе знаний, промптах, валидаторах; когда расширять корпус.
- **Ожидание доверия.** Цифры на дашбордах совпадают с event-store; для любого артефакта есть трасса до исходного документа.

### Platform- / SRE-инженер

- **Хочет.** Надёжный локальный стек, предсказуемое потребление ресурсов, наблюдаемые отказы.
- **Вход.** Compose-профили, метрики, runbooks.
- **Выход.** Операции up/down, решения по ёмкости, реакция на инциденты.
- **Точки касания.** [infra/compose/](../../infra/compose/), [docs/11-operations/](../11-operations/).

## Стейкхолдеры governance

### Tech Lead / Архитектор

- **Хочет.** Чтобы контракты, traceability и порядок из [docs/00-methodology/development-process.md](../00-methodology/development-process.md) соблюдались.
- **Вход.** ADR, traceability-матрицы, diff-ы.
- **Выход.** Одобрение ADR, блокирующий ревью на shortcut-ы, обходящие docs или валидаторы.

### Ревьюер по безопасности / Compliance

- **Хочет.** Чтобы пользовательский ввод не утекал в другие диалоги, чтобы scoping артефакт-хранения был корректным и чтобы ничего из `incoming-docs/raw/` не переопубликовывалось молча.
- **Точки касания.** [docs/03-architecture/deployment-view.md](../03-architecture/deployment-view.md), правила изоляции диалогов, scoping MinIO.

## AI-ассистент (Claude Code)

Не «стейкхолдер» в человеческом смысле, но участник этого репозитория. Его роль описана в [CLAUDE.md](../../CLAUDE.md) и ограничена [docs/00-methodology/](../00-methodology/). От него ожидается:

- читать docs перед написанием кода,
- продуцировать черновики контрактов, промптов, валидаторов и тестов,
- никогда не обходить процесс разработки.
