# Vision

## Зачем существует FE-Bot

ML-команды тратят большую долю любого нового проекта на одни и те же низкорычажные шаги: уточнить задачу, профилировать незнакомые данные, искать предыдущие знания о домене, вручную ваять первые признаки, генерировать синтетический датасет, чтобы разблокировать прототипирование, и собирать запускаемый training pipeline. Эти шаги повторяются от проекта к проекту, но каждый проект делает их с нуля.

**FE-Bot** (Feature Engineering Bot) — мультиагентный помощник, который проводит пользователя через эти шаги как через структурированный диалог. Сначала пользователь готовит структурированную базу знаний по своему домену, затем формулирует ML-задачу на естественном языке; система использует RAG поверх этой базы и детерминированный LangGraph-workflow, чтобы выдать типизированный воспроизводимый пакет: определения признаков, синтетический обучающий датасет, рекомендованную модель с training config и запускаемый pipeline-скрипт.

**Какую ценность получает бизнес.** Старт нового ML-проекта сводится к одной управляемой сессии (целевое значение — до 15 минут для эталонного сценария, см. [G-01](goals.md)); доменные знания накапливаются в базе знаний и переиспользуются между проектами, а не живут в головах; каждое решение (почему именно этот признак, эта модель) подкреплено ссылкой на источник и проверяемо.

## Что на входе и что на выходе

Если коротко: **на входе — доменные документы и разговор о задаче, на выходе — готовый к запуску ML-пакет**. Система работает в два прохода, а третья стадия наблюдает за ними.

```text
 документы домена              описание ML-задачи в чате
 (md, txt, pdf, docx,          («Нужен классификатор типа
  xlsx, csv, json)             морской цели по данным РЛС»)
        │                             │
        ▼                             ▼
 ┌────────────┐   kb_version   ┌────────────┐
 │   SETUP    │ ─────────────▶ │  RUNTIME   │ ─────▶  archive.zip
 │ база знаний│  (опубликована)│ диалог → ML│         (признаки, синт. датасет,
 └────────────┘                └────────────┘          training_config, pipeline.py…)
        │                             │
        └──────── события ────────────┴──────▶  ANALYTICS (дашборды, audit trail)
```

| Стадия | На входе | На выходе | Для кого |
| --- | --- | --- | --- |
| **Setup** | Файлы доменных документов (справочники, описания данных и задач, глоссарии, правила валидации); параметры проекта; решения пользователя по сгенерированным карточкам | Опубликованная версия базы знаний — утверждённые RAG-карточки, проиндексированные чанки, отчёт проверок — и сообщение «Knowledge Base ready» | Администратор базы знаний / доменный эксперт |
| **Runtime** | Диалог на русском или английском: описание задачи, описание *имеющихся* данных (поля, объём, классы), ответы на уточняющие вопросы, подтверждения | `archive.zip`: подтверждённые признаки с источниками, синтетический обучающий датасет, рекомендованная модель с `training_config.yaml`, запускаемый `pipeline.py`, метаданные для воспроизводимости | ML-инженер / data scientist |
| **Analytics** | События Setup и Runtime (пользователь почти ничего не вводит — в основном читает) | Дашборды качества и сквозной audit trail | Product / platform-owner |

Два важных уточнения:

- **Реальные данные пользователя в систему не загружаются.** Пользователь *описывает* свои данные в диалоге, а система строит по этому описанию синтетический датасет (так устроены [RUNTIME-04](../02-system/features/RUNTIME-04-data-profiling.md) и [RUNTIME-10](../02-system/features/RUNTIME-10-data-generation.md)).
- **Модель не обучается.** На выходе — рекомендация и скрипт, который пользователь запускает у себя.

Полный перечень форматов, параметров и файлов — в [system-overview.md](../02-system/system-overview.md#входы-и-выходы-системы).

## Три стадии, а не одна

FE-Bot поставляется как **три отдельные пользовательские стадии**, у каждой из которых своя UI-поверхность и свои критерии приёмки:

1. **Setup.** Мастер-UI из 11 шагов, который превращает сырые доменные документы → разобранные и классифицированные секции → типизированные RAG-карточки (schema, task, analytics, feature pattern, validation rule, question template) → чанки → embeddings → векторный индекс → retrieval smoke tests → опубликованную базу знаний. Цикл принадлежит пользователю: он загружает файлы, ревьюит сгенерированные карточки, чинит metadata и подтверждает публикацию. **Setup обязан завершиться сигналом "Knowledge Base ready" до открытия следующей стадии.**

2. **Runtime.** Управляемый ML-диалог. Восемь значений фазы в `ContextMemory` (Initialization → Task Discovery → Data Profiling → Domain Context → Feature Synthesis → Data Generation → Model Selection → Export; пользователь видит семь последних), управляемые `LangGraph` поверх типизированной `ContextMemory`, опирающейся на базу знаний из стадии 1.

3. **Analytics.** Дашборды, замыкающие петлю обратной связи: воронки пользовательских сессий, качество retrieval, latency агентов и rate repair-loop-ов, жизненный цикл RAG-контента, исходы генерации признаков, качество синтетических датасетов, распределение рекомендаций моделей, доменные feature-store-виды и audit trail от исходного документа до экспортированного артефакта.

Изменение на любой стадии тестируется изолированно, но стадии разделяют одну базу знаний, один контракт `ContextMemory` и один audit trail.

## Что такое FE-Bot

Docs-as-code, contract-first мультиагентная платформа, которая:

- принимает сырые пользовательские документы и превращает их в валидированную retrievable базу знаний (Setup),
- захватывает намерение пользователя и уточняет ML-задачу (Runtime),
- профилирует поля данных, объём и распределение классов,
- извлекает доменный контекст из типизированной RAG-базы,
- синтезирует кандидатов признаков и валидирует их детерминированно,
- эмитит `GenerationSpec`, потребляемый Python-инструментами (а не текстовой генерацией LLM), чтобы построить синтетическую обучающую выборку,
- ранжирует кандидатов моделей и эмитит `training_config`,
- экспортирует полный пакет как воспроизводимый архив,
- выставляет дашборды для каждого сигнала качества, важного на runtime (Analytics).

## Чем FE-Bot не является

- **Не** AutoML training service. Не обучает production-модели.
- **Не** свободный чат-бот. Каждый агент возвращает типизированный, валидированный по схеме вывод.
- **Не** LLM-as-data-generator. Датасеты производятся Python, никогда — token-генерацией.
- **Не** автономный принимающий решения. Пользователь подтверждает наборы признаков, модели и экспорт.

## Целевые пользователи

- **ML-инженеры / data scientists / аналитики** — ведут Runtime-диалог и потребляют экспортированные пакеты.
- **Администраторы базы знаний RAG / доменные эксперты** — ведут Setup-мастер и курируют карточки.
- **Product / platform-owners** — читают Analytics-дашборды.

## Эталонный сценарий

Пользователь только что установил FE-Bot:

1. Открывает Setup-мастер, загружает папку Markdown/PDF документов про морскую радиолокацию, смотрит, как система извлекает секции, генерирует RAG-карточки, валидирует metadata, строит чанки и embeddings и прогоняет retrieval smoke-тесты. Получает сообщение **«Knowledge Base ready»**.
2. Открывает чат и пишет: *«Нужен классификатор типа морской цели по данным РЛС»*. Система извлекает `task_type=classification`, `domain=naval`, `data_source=radar`, задаёт уточняющие вопросы, поднимает radar-doменные карточки из своей базы знаний, предлагает базовые/производные/interaction-признаки со ссылками на `evidence_doc_ids`, прогоняет валидацию признаков, генерирует сбалансированный многоклассовый синтетический датасет, рекомендует `XGBoostClassifier` с `f1_macro` и экспортирует `archive.zip`.
3. На следующий день product-owner открывает Analytics и видит новую сессию в дашборде, retrieval hit rate, latency агентов и trace-цепочку от исходных документов пользователя до экспортированных артефактов.

## Критерий успеха

Новая ML-задача — включая построение свежей базы знаний для незнакомого домена — может быть доведена от однострочного описания до воспроизводимого инспектируемого пакета за одну управляемую сессию, причём каждый артефакт прослеживается обратно к документу или RAG-карточке.
