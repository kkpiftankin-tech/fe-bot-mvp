# Границы MVP, допущения и риски

Что входит в первую версию, на что система опирается и что может пойти не так. Источник по Runtime — разделы 16–18 исходного [бизнес-документа](../../incoming-docs/raw/Бизнес%20Feature%20Engineering%20%26%20Data%20Generation%20Bot.md); границы Setup — [SETUP-01 §4](../02-system/features/SETUP-01-setup-wizard.md). Что именно подаётся на вход и отдаётся на выходе — в [vision.md](vision.md#что-на-входе-и-что-на-выходе).

## Что входит в MVP

### Runtime

1. Web chat interface.
2. Диалог из 7 фаз (Task Discovery → Export).
3. NLU для базовых intents и извлечение ключевых слотов.
4. `ContextMemory`.
5. RAG по коллекциям: glossary, domain profiles, feature library, model recommendations, question templates.
6. Синтез признаков для одного основного сценария — **табличная классификация**.
7. Генерация синтетических табличных данных.
8. Рекомендация top-3 моделей.
9. Экспорт: `features.json`, конфигурация обучения, `data_generator.py`, `pipeline.py`, `metadata.json`, zip-архив. Полный состав архива — в [system-overview.md](../02-system/system-overview.md#runtime-выход).

### Setup

- Мастер из 11 шагов: загрузка документов → парсинг и классификация → генерация RAG-карточек → ревью → валидация metadata → chunking и индексация → retrieval-тесты → публикация KB → отчёт.
- Форматы документов: `md`, `txt`, `pdf`, `docx`, `xlsx`, `csv`, `json`.

## Ограничения MVP

### Runtime

1. Один основной домен для тестирования, например `naval_radar`.
2. Ограниченный набор моделей: XGBoost, LightGBM, Random Forest (по бизнес-документу; [RUNTIME-11](../02-system/features/RUNTIME-11-model-selection.md) описывает более широкий набор моделей по умолчанию).
3. Ограниченный набор feature patterns.
4. Без автоматического подключения к реальным БД — данные пользователя описываются в диалоге, датасет синтетический.
5. Без production deployment модели.
6. Подтверждение человеком перед экспортом.

### Setup

- Один активный setup job на пользователя и одна активная версия KB на проект.
- Базовые retrieval smoke-тесты; без сложного согласования несколькими экспертами.
- OCR для сканированных PDF не входит в MVP.
- Публикация KB с предупреждениями retrieval-тестов по умолчанию запрещена.

## Критерий готовности MVP

MVP готов, если на тестовом happy path (`naval_radar`) система:

1. завершает все 7 фаз;
2. корректно сохраняет контекст;
3. генерирует минимум 19 признаков;
4. генерирует синтетическую выборку;
5. рекомендует top-3 модели;
6. создаёт все обязательные артефакты и возвращает архив;
7. логирует основные решения;
8. не требует ручного вмешательства разработчика.

Сквозной сценарий приёмки (12 шагов от запуска до запуска `pipeline.py`) — в разделе 15.1 исходного документа и в [UC-FE-02](../02-system/use-cases/UC-FE-02-create-feature-set/use-case.md).

## Допущения

1. Пользователь способен описать задачу хотя бы на базовом уровне.
2. База знаний содержит релевантные доменные документы.
3. У системы есть доступ к локальному или серверному LLM API.
4. Система может хранить состояние и артефакты.
5. Для MVP допускается генерация синтетических данных без подключения к реальным данным.

## Ограничения предметной области

1. Модель LLM малая, поэтому сложные рассуждения декомпозируются (см. [C-01](constraints.md)).
2. Качество системы критически зависит от RAG-корпуса.
3. Сгенерированные данные синтетические и не заменяют реальные.
4. Рекомендованная модель не гарантирует production-качества без обучения и валидации.
5. Формулы признаков проверяются валидаторами.
6. Ключевые решения подтверждает пользователь.

## Риски

| Риск | Влияние | Митигирующая мера |
| --- | --- | --- |
| Маленькая LLM ошибается в извлечении intent и entities | Высокое | Confidence, уточняющие вопросы, regex fallback, нормализация через RAG |
| Неполный RAG-корпус | Высокое | `need_more_context`, работа куратора, версионирование |
| Галлюцинации признаков | Высокое | Обязательный evidence, валидаторы, подтверждение пользователем |
| Некорректные формулы | Высокое | Парсер формул, проверка единиц, validation agent |
| Невалидный `pipeline.py` | Среднее / высокое | Шаблоны кода, статические проверки, тесты |
| Слишком много признаков | Среднее | `MAX_FEATURES`, `MAX_INTERACTIONS`, проверка мультиколлинеарности |
| Неверная рекомендация модели | Среднее | Top-N, объяснение, выбор человеком |
| Потеря контекста | Высокое | Персистентный `ContextMemory`, снимки по фазам |
| Низкая скорость ответа | Среднее | Кэширование, короткие промпты, RAG top-K, декомпозиция по агентам |
| Пользователь не понимает ML-термины | Среднее | Простые объяснения, глоссарий, quick replies |

Риски Setup (недоступность LLM, embedding-модели или Vector DB; дубликаты файлов; ошибки парсинга) разобраны в [SETUP-01 §7.3 и §22](../02-system/features/SETUP-01-setup-wizard.md) и [rag-failure-modes.md](../06-rag/rag-failure-modes.md).
