# SETUP-03. Реестр источников

## Назначение

Управляемый, просматриваемый реестр каждого загруженного пользователем документа. Каждая запись — **единый якорь**, к которому позже привязываются карточки, чанки, embeddings и ссылки audit-trail.

## Бизнес-ценность

Без реестра цепочка от «PDF пользователя» до «этого экспортированного признака» ломается в момент повторной загрузки или переименования файла. Реестр делает эту цепочку first-class объектом.

## Вход и выход

- **Вход.** Принятые файлы из [SETUP-02](SETUP-02-document-upload.md).
- **Выход.** Запись реестра на каждый документ (`SourceDocument`: `file_id`, `status`, `section_count`, `card_count`, `tags`) — якорь, к которому привязываются секции, карточки, чанки и audit trail.

## Пользовательский сценарий

1. Пользователь открывает вид Source Registry внутри мастера.
2. Видит таблицу всех загруженных файлов: имя, MIME type, размер, checksum, статус (`uploaded`, `parsed`, `processed`, `review_required`, `error`), кто загрузил, когда, число извлечённых секций, число сгенерированных RAG-карточек.
3. Кликает на строку, чтобы увидеть детали документа: metadata, оригинальный preview, ссылки на parsed-секции, ссылки на сгенерированные карточки.
4. Может перезапустить парсинг отдельного документа или убрать его из KB (soft-delete с сохранением audit trail).

## Связанные требования

- BR-FR-Setup-031..034 (идентичность источника, статус, просматриваемость, удаляемость).
- NFR-Audit-001 (каждое изменение state логируется).

## Связанные сервисы

- Source Registry Service, Frontend Source Registry View, Database (PostgreSQL), Audit Service.

## Связанные контракты

- `SourceDocument` (`schemas/setup.py`): `source_document_id`, `file_id`, `status`, `uploaded_at`, `processed_at`, `section_count`, `card_count`, `tags`.

## Критерии приёмки

- У каждого загруженного документа ОБЯЗАН быть ровно один `source_document_id`.
- Переходы статусов ОБЯЗАНЫ быть append-only и видимы в audit trail.
- Повторный парсинг документа НЕ ОБЯЗАН менять его `source_document_id` (это тот же источник).
- Тест: `tests/component/test_source_registry.py`.

## Вне scope

- Per-document access control (в MVP каждый с доступом к KB видит все источники).
