# PLATFORM-01. Поверхность Backend API

## Назначение

Единый сервис FastAPI, выставляющий каждую операцию, которую делает UI и внешние клиенты: старт / возобновление Runtime-сессии, отправка шага пользователя, управление Setup, получение аналитики, скачивание артефактов, запрос audit. Владеет аутентификацией, валидацией запросов и маршрутизацией в LangGraph-оркестратор + sub-сервисы.

## Бизнес-ценность

Без одной канонической API-поверхности три разных фронтенда (чат / мастер / дашборд) дрейфуют в три разные формы запросов. Централизация — то, что удерживает контракты стабильными.

## Пользовательский сценарий

Каждое UI-действие — *перетянуть файл для загрузки*, *кликнуть «Start project»*, *отправить сообщение в чат*, *скачать archive.zip* — это один типизированный FastAPI-запрос с Pydantic-телом, валидированным до любого нижестоящего вызова.

## Связанные требования

- BR-FR-Platform-001..003 (единая точка входа, валидация схемы, контракт ошибок).
- NFR-Sec-003 (тела запросов валидируются против Pydantic до dispatch).
- NFR-Obs-001 (per-request структурированный лог).

## Связанные сервисы

- API Backend (FastAPI), Auth Service, Setup Orchestrator, LangGraph Orchestrator, Analytics Service, Artifact Service.

## Связанные контракты

- `schemas/api/*` — один Pydantic-класс на request и response эндпоинта.

## Критерии приёмки

- Все эндпоинты ОБЯЗАНЫ возвращать либо типизированный response, либо типизированный конверт ошибки (`{ error: { code, message, details } }`).
- 4xx-ошибки НЕ ОБЯЗАНЫ роняться; 5xx-ошибки ОБЯЗАНЫ репортиться через observability-pipeline.
- Тест: `tests/integration/test_api_contracts.py`.

## Вне scope

- Публичное интернет-экспонирование / тонкая настройка rate limiting (MVP крутится на `localhost`).
